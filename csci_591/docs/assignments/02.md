# Assignment 02: Fuzzing

## Description

Write a fuzzer which utilizes grammars or templates and mutations to generate session input for the Palimpsest MCP server.

The fuzzer may be written in any programming language.

### Target Information

Palimpsest is a binary-only MCP server for the CSCI 591 fuzzing assignment. It
manages keyed document workspaces and snapshots. Your
target is the `palimpsest` executable in this package. The expected behavior
of each tool is in the `SPEC.md` file included in the Palimpsest packages.

#### Setup
- On Apple Silicon macOS, use the `darwin-arm64` package and run
  `./palimpsest` directly. Keep `libclang_rt.asan_osx_dynamic.dylib` in the
  same directory as the executable.
- On Linux x86-64, run `./palimpsest` directly if its runtime libraries are
  available. Otherwise, use the supplied container definition.
- On another host, use the Linux x86-64 package in a container whose engine
  supports `linux/amd64` images. If you are on Windows, consider using Windows Subsystem for Linux 2 (WSL 2) or Docker.

#### Running
The Palimpsest executable can be run from the command line: `./palimpsest`. It reads one JSON-RPC message per line
from standard input and writes one response per line to standard output.
Diagnostics go to standard error. **Be sure to capture both standard output and standard error from your fuzzer.**
This will help you recognize a crash and identify its cause. Palimpsest uses MCP protocol version `2025-11-25`.

For the Linux package, build and run the supplied container with Docker or
Podman when direct execution is unavailable:

```sh
docker build --platform linux/amd64 -f Containerfile -t palimpsest .
docker run --rm -i --platform linux/amd64 palimpsest
```

Substitute `podman` for `docker` if that is your container engine. Send the
same newline-delimited requests to the container's standard input.

On macOS, Gatekeeper may quarantine an executable downloaded from the course
site. After verifying the archive's SHA-256 digest, you can remove the quarantine property
from the extracted course directory if macOS refuses to launch it:

```sh
xattr -dr com.apple.quarantine palimpsest/
```

Here `palimpsest/` is the extracted directory containing both the executable
and its sanitizer runtime.

The examples below are pretty printed for readability. When sending them to
Palimpsest, serialize each complete JSON object onto one line.

Begin each process with an `initialize` request and a
`notifications/initialized` notification:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-11-25",
    "capabilities": {},
    "clientInfo": {
      "name": "student-fuzzer",
      "version": "1.0"
    }
  }
}
{
  "jsonrpc": "2.0",
  "method": "notifications/initialized"
}
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/list",
  "params": {}
}
```

The notification has no response. Send further calls as `tools/call` requests:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "workspace_create",
    "arguments": {
      "key": "example-workspace-secret"
    }
  }
}
```

Read identifiers from `result.structuredContent` and use them in later calls.
Pass the workspace key as `key` in subsequent tool arguments. Do not assume
that identifiers have a particular format. Tool failures set
`result.isError` to `true`; malformed MCP requests may instead receive a
JSON-RPC `error`.

#### Fuzzing

Generate *sequences of valid tool calls* from a grammar. Keep track of the
workspaces, documents, and snapshots returned by the server so later grammar
productions can refer to them. Track the key for each workspace.
Include empty content, boundary lengths, repeated content, multiple workspaces, and occasional invalid or stale identifiers.
A test case may use a fresh server process or a fresh workspace within a persistent process. If using a persistent process, you will need
to be able to reproduce all the interactions from when the process was started until it crashed.

Investigate crashes, sanitizer reports, and responses that violate the
behavior in `SPEC.md`, included in the package. Save the exact message sequence and random seed for
each finding, then minimize the sequence while preserving the failure.

If you use the Linux container, you may build your fuzzer into a derived image
and have it launch `/usr/local/bin/palimpsest` as an ordinary subprocess. This
is much faster than starting a new container for every generated test case.

## Submissions

Please provide the following as part of your submission:

- A brief findings report describing any discovered crashes and explaining their expected causes
- A brief summary and diagram of your fuzzer's architecture
    - This summary will be used by the instructor and other students to quickly understand the design of your fuzzer
    - Please include:
        - Description of how one or more grammars were used
        - Mutation operators implemented
        - Any other interesting or helpful details
- Source code for your fuzzer
- Build instructions and/or build scripts
- For any crashes or suspected vulnerabilities:
    - The input generated by your fuzzer
    - Any associated log files related to the finding

Submissions should be provided as a ZIP file to the assignment through Canvas.

## Grading

The assignment will be graded based on:

- (25%) A fuzzer capable of generating unique, random inputs that can exercise `palimpsest`
- (20%) Complete submission including all required components (see [Submissions](#submissions) for more information)
- (10%) *At least one* crash, found by your fuzzer, that is described in the findings report
- (15%) *At least two* crashes, found by your fuzzer, that are described in the findings report
- (30%) Demonstration of understanding of your fuzzer's architecture and implementation
