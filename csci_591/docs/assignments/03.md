# Assignment 03: Symbolic Execution

## Description

Write a symbolic execution engine which utilizes a tree-walk interpreter to perform symbolic execution on individual functions written in a specific subset of the C programming language. Your symbolic execution engine should accept as input the path to a C source file and the name of a function defined in that source file to execute. It should output information about the symbolic execution of the function. While there are a number of ways we could designate a target or goal to reach inside a function, we will use a `return 1;` statement to indicate a target to reach in the function. A symbolic state which reaches this goal should be used when providing constraints and concrete values for reaching the goal.

The symbolic execution engine will manage symbolic states which store information about symbolic expressions, path conditions, and the next statement to execute. When a conditional branch is reached, the current symbolic state will be split into two new possible states. The path condition of a symbolic state should be checked for feasibility before resuming execution. If the path condition for a symbolic state is not satisfiable (*UNSAT*), then the symbolic state is marked as *infeasible* and no further execution is needed. If the path condition for a symbolic state is satisfiable (*SAT*), then further execution of that path should be performed until either another conditional branch is reached or all statements have been executed.

### A Subset of C

Only a small portion of the C language needs to be supported by your symbolic execution interpreter. All variables should be treated as signed integers that are unbounded; i.e., you do not need to be concerned with integer overflow or underflow and can assume sufficient storage to represent any integer value.

Your interpreter should be capable of symbolically executing the following statements:

  - variable declaration (`int x;`, `int x = y;`)
  - variable assignment (`x = y;`)
  - standalone increment and decrement expressions (`i++;`, `x--;`)
  - if- and if-else-statements (`if (x == 0) { ... }`, `if (x == 0) { ... } else { ... }`)
  - while loops (`while (x < 10) { ... }`)
  - return statements (`return x;`)

Your interpreter should be capable of symbolically executing the following expressions:

  - arithmetic expressions
    - integer literals (`41`)
    - integer variables (`x`)
    - addition (`x + y`)
    - subtraction (`x - y`)
    - multiplication (`x * y`)
    - negation (`-x`)
    - pre- and post-increment (`++x`, `x++`)
    - pre- and post-decrement (`--x`, `x--`)
  - boolean expressions
    - equality (`x == y`)
    - inequality (`x < y`, `x <= y`, `x > y`, `x >= y`)
    - logical conjunction (`x > 0 && x < 10`)
    - logical disjunction (`x < 0 || x > 10`)

For this assignment, `&&` and `||` will only be used with side-effect-free operands whose evaluation is defined. You do not need to model short-circuit evaluation.

Additionally, recall that the semantics of C are such that expressions which evaluate to an integer can be interpreted as true or false. A zero value is interpreted as false, and a non-zero value is interpreted as true.

$$
\begin{prooftree}
    \AxiomC{$\langle e, \sigma \rangle \Downarrow_{\mathrm{int}} n \quad n = 0$}
    \RightLabel{Int-False}
    \UnaryInfC{$\langle e, \sigma \rangle \Downarrow_{\mathrm{cond}} \mathrm{false}$}
\end{prooftree}
$$

$$
\begin{prooftree}
    \AxiomC{$\langle e, \sigma \rangle \Downarrow_{\mathrm{int}} n \quad n \neq 0$}
    \RightLabel{Int-True}
    \UnaryInfC{$\langle e, \sigma \rangle \Downarrow_{\mathrm{cond}} \mathrm{true}$}
\end{prooftree}
$$

These rules describe concrete evaluation of a condition. When evaluation yields a symbolic expression $s$, the interpreter explores both outcomes by adding either $s = 0$ or $s \neq 0$ to the path condition and discarding any infeasible branch.

Finally, statements which are function calls without assignment should be ignored (e.g., `printf("x: ", x);`) and considered `NOP`s. Assignment statements which are assigning the result of a function call (e.g., `result = f(x, y)`) should be treated the same as variable declarations and the assignment target (`result`) should be associated with a new, unconstrained symbolic value.

### Loop Bound

Explore at most 10 executions of each `while` loop body on a symbolic path. After the tenth execution, evaluate the loop condition once more. Continue along a feasible exit branch. If the condition can still be true, stop exploring that branch and mark it as *truncated*. A truncated branch is neither an infeasible state nor a completed feasible path. Report the number of truncated branches; when it is nonzero, the feasible-path and infeasible-state counts cover only the explored portion of the function, not every possible execution.

### Output

After symbolically executing a specified C function, your symbolic execution engine should output the number of symbolic states that were infeasible, the number of feasible paths through the function, the constraints for a feasible path that reached the target statement, and a concrete input which will cause normal execution of the program to reach the target statement. If no feasible path reaches a `return 1;` statement, report that no feasible path to the target was found. For a feasible target path, also provide a second assignment to the symbolic input variables that satisfies its constraints and differs from the first assignment in at least one variable. If no second assignment exists, report that the first assignment is the only one satisfying those constraints. Unconstrained values introduced for function-call results count as symbolic input variables for this purpose.

### Clarifying Points

- The interpreter needs to understand that a return statement ends execution of the function, but it does not need to manage tracking a return value.
- Just as in C, variable names reused in a declaration within an inner scope will shadow a variable of the same name declared in an outer scope. Consider using a stack of variable declarations which correspond to the nested scopes. Lookup of variables requires traversing the stack, starting from the top.

## Resources

### Parsers

Your symbolic execution engine will need to handle parsing C programs. There is no need to write your own parser, instead consider using an existing parser such as [Tree-sitter](https://tree-sitter.github.io/tree-sitter/).

### SMT Solvers

You are welcome to use any SMT solver you prefer, but I recommend using the [Z3 theorem prover](https://www.microsoft.com/en-us/research/project/z3-3/) as there are existing wrapper libraries for many programming languages and it also supports SMT-LIB2 for languages without a native interface.

## Test Program

Save the following test program as `test.c`. It exercises the interpreter and assists in verifying its correctness.

```c
#include <stdio.h>
#include <stdlib.h>

int y_init;

int
f() {
  return y_init;
}

int
test(int x) {
  int y = f();
  if (x > y) {
    int i = 0;
    while (i < 10) {
      x--;
      i++;
    }

    if (x == y) {
      puts("nope");
      return 0;
    } else {
      if (x < y) {
        // Get here
        puts("got it!");
        return 1;
      } else {
        puts("not here");
        return 0;
      }
    }
  }
  puts("wrong way");
  return 0;
}

int
main(int argc, char *argv[]) {
  int x = atol(argv[1]);
  y_init = atol(argv[2]);
  int result = test(x);

  printf("result: %d\n", result);

  return 0;
}
```

An example run on this program could look like:

```console
$ symex test.c test

Number of infeasible states: 11
Number of feasible paths through function: 4
Number of feasible paths to reach target statement: 1
Number of truncated paths: 0

Constraints to reach target statement:
x_0 > f_result_0
x_0 - 10 != f_result_0
x_0 - 10 < f_result_0

Concrete values to reach target statement:
x_0 = 0
f_result_0 = -1

Alternative concrete values for the same path:
x_0 = -1
f_result_0 = -2
```

Here `f_result_0` is the symbolic value returned by `f()`. In this program, `f()` returns `y_init`, so running the compiled program with either `0 -1` or `-1 -2` reaches `return 1;`.
